# Visual reference — Interactive Power BI CV

Per-visual catalogue of every object on every report page. **Update at every session end that touched a visual** (any file under `Report/definition/pages/**/visuals/**` or a bookmark/interaction change). Missing rows or stale rows both defeat the point.

Built for a greenfield single-report build: no "legacy vs new" columns, no rename history yet.

---

## 1. Format contract

Each report page gets its own §. Under it, one table with these columns:

| Col | Meaning |
|---|---|
| `name` | `snake_case` object name from the Selection pane (see prefixes in CLAUDE.md §5). MUST be meaningful — no `Rectangle 42`. |
| `type` | Power BI visual type or shape kind (`button`, `image`, `shape.rectangle`, `slicer`, `card`, `textbox`, `matrix`, custom visual name, etc.). |
| `pos` | `X,Y / W,H` in report-pixel coordinates on the 2072 × 1020 canvas. |
| `role` | One line: what job does this visual do? (e.g. "sheet tab: Experience", "formula-bar name box", "story/list toggle segment: Story"). |
| `bindings` | Field bindings by role (`data`, `values`, `category`, filter, tooltip, etc.). Format: `role: table.column [display label if overridden]`. `-` if none. |
| `states` | Static / hover / press / selected images or fills where applicable. `-` if none. |
| `interactions` | Action or interaction overrides on this visual (`type: Default/DataFilter/HighlightFilter/NoFilter` per source visual). `-` if all defaults. |
| `bookmarks` | Bookmarks that toggle this visual's visibility, or `-`. |
| `notes` | Anything else: `<TODO: VERIFY!>` markers, deviations from `_context/design.md`, load-blocker cautions. |

Above the table, per page, list: page dimensions, page background (image or fill), and any page-level filters.

**Button tooltips, as of 2026-10-03 (45 action buttons).**

- **14 navigating buttons set `visualLink.showDefaultTooltip: false`**, which kills Power BI's "click here to follow" hover hint: the 7 sheet tabs, `btn_ribbon_file`, the 4 overlay menu buttons, and the dialog's Continue and Cancel.
- **12 buttons carry a custom `tooltip` with `showDefaultTooltip: true`**, which *replaces* the hint with their own text: `btn_ribbon_help`, `btn_ribbon_clear_filters`, the 4 `btn_filter_hint_*`, `btn_overlay_close`, `btn_overlay_about_recent_open`, the 3 contact links and `btn_exec_highlight_link`. `false` here would suppress the custom text along with the hint (§3.23).
- **19 buttons have no `visualLink` at all** and need nothing: the 4 ribbon blockers, `btn_block_exec_summary_text`, the 2 contact blockers, the 2 panel covers, the 9 dialog tiles and `btn_ribbon_home`.

A sweep that flags every `!= false` therefore yields false positives — discriminate on "has a custom `tooltip`", not on the flag alone.

**Every tab suppresses container chrome fully:** `title`, `subTitle`, `background`, `border`, `dropShadow`, `divider`, `visualHeader` all `show:false` under `visualContainerObjects`, plus button `outline` `show:false` at global / default / hover selectors. Applied to defeat the theme-injected 1 px hover border. **Do not add `show` to `padding` or `spacing`** — those container properties carry numeric values, not a visibility toggle; Fabric schema-validates the extra key and blocks the report.
